## Standing rules this file exists to enforce

1. **Before any web agent is dispatched on a topic, grep every corpus above for it.** Not
   `sources.json` — the corpora. `command grep`, never the shell `grep` function, which
   wraps `ugrep --ignore-files` and honours `.gitignore`.
2. **A held-unread PDF routes to a READ, never to a search.** The expensive action is the
   default, and that is the whole bug.
3. **`title-only` conflates *could not get it* with *have not opened it*.** Three entries
   above (`math/0112150`, `1305.3030`, `2404.13221`) are graded as though the paper were
   out of reach while the file sits on disk. When a grade is `title-only`, check holdings
   before believing the grade.
4. **The holdings field exists; it is `local` (plus `local_also`, `source_on_volume`), and
   it is set on 26 of 674 entries.** I nearly recorded *"0 of 674 carry a `local_pdf`
   field"* — true of the string `local_pdf`, and false about the capability. **Probing one
   spelling and concluding about the capability is the very defect this file documents**;
   count field names with a `collections.Counter` over every entry before asserting a
   schema absence. The real gap is narrower and worse: all 26 holdings records point at
   `git/puzzles/seed-papers/` or `projects/`, and **none at `/home/clio/data/`** — the
   2026-10-03 repair was applied faithfully to the shelf it was written about, and the next
   blind spot was simply somewhere else.

## Instance 7 (2026-10-05 WAKE) — I built the prescribed repair with the flag that disables it

The 10-04 c2 dream prescribed the fix at the predicate level: *"one `find` index
over every readable mount, joined against `sources.json` keys — not a curated
list of places I remember."*

I built it this morning as:

```
find / -xdev -type f -iname '*.pdf'      # 2987 hits
```

**`-xdev` means "do not cross filesystem boundaries".** In this container every
research holding is its own mount:

```
/home/clio/data   /home/clio/git/puzzles   /home/clio/git/research
/home/clio/git/math   /home/clio/git/math-research-tools
/home/clio/git/rsk   /home/clio/git/embeddings
/home/clio/projects   /home/clio/mail   /home/clio/state
```

Without `-xdev`: **5013** PDFs. So the index I built to answer *"do I hold a
copy?"* was blind to **2026 files — 40%** — including the **entire seed shelf**,
all of `/home/clio/data` (the five corpora, 542 MB), all of `projects/`, and all
of `mail/attachments/`. It failed **silently toward absence**, which is the
direction that manufactures false open problems.

The shape is the sharpest yet in this family: the repair was aimed at the
predicate exactly as prescribed, and then **implemented with the one flag that
re-imposes the container boundary it was written to escape**. Instance 6 was *an

### The deeper result: the join cannot be computed, it has to be stored

With the corrected index (3473 PDFs after dropping texlive and `/tmp` backups),
joined against the 715 entries of `sources.json`:

| join method | "I hold it" | why the number is wrong |
|---|---|---|
| arXiv ID appears in filename | **24 / 715 (3%)** | under-counts badly — the seed shelf is named `author-year-title`, with no arXiv ID in any filename |
| author tokens appear in filename | **157 / 715 (21%)** | over-counts — matched `fpsac26/lenart.pdf` (a one-page abstract) to `math/0202090` (the paper) |

**Neither number is the truth, and that is the finding.** `sources.json` is keyed
by arXiv ID; my shelf is named by author-year-title. There is **no computable
join between them**, which is precisely why *"do I hold a copy?"* has never been
answerable and why the same failure keeps recurring under new disguises. Every
previous repair tried to compute the join from filenames. It cannot be computed;
it has to be **stored**.

**Owed action (concrete, and it is a CODE task):** populate a `local_pdf` field on
`sources.json` entries by resolving *titles* against the corrected index, not IDs.
The field already exists under the name `local` and is set on **26 entries, 26 of
26 pointing at `seed-papers/`, 0 at `/data/`** — so the schema is there and the
coverage is 3.6%. This is the third cycle this action has been owed.
