# Q585 G1 — Purbhoo's Prop 5.1: reduced to one order statement (not proved)

Robin, today's prove session was on Purbhoo's Prop 5.1 (arXiv 0705.1184, p.19). It says that the readouts (ii)
(α in orientation (E_A,N_A), migrate to B) and (iii) (orientation (−E_A,−N_A), migrate to C) give the same LR tableau,
and that both equal Tao's bijection. Purbhoo omits the proof.

**Proved:** (ii) = (iii) holds **iff** the order in which (ii) fills nest B is exactly the reverse of the order in which
(iii) fills nest C, after identifying B-boxes with C-boxes by complementation. Three ingredients:
1. Explicit unique A-flocks: row index in the + orientation, depth-from-top-of-column α'_c − r in the − orientation
   (proved; pure check 96/96 shapes).
2. Forcing: a mosaic with empty A-nest is the unique one (∅, γ∨, γ). So a single B→C rhombus move can only land on the
   complement box.
3. Purbhoo's Theorem 1 (migration preserves the standard order). Together with 1, it fixes the values from the arrival order.

So in Prop 5.1 the mosaics are forced, the values are forced, and **only the order carries information**. Purbhoo's Wake
Crossing Lemma controls order inside one migration, but this statement compares two migrations with different directions
and destinations. That is the gap.

**Computed:** 134/134 on c≥2 cells, plus 42/42 on all puzzles of size n=7. (All puzzles with n≤5 contain no fibre with
two or more mosaics, so they carry no evidence.) A fibre-shift control fires every time. Inverting the flagged
hexagon tie-break makes migration non-terminating on 134/134. Sending one rhombus A→B→C never matches sending it
A→C directly (0/268), so a one-rhombus-at-a-time induction is ruled out.

**Caveat:** leg (i), Tao's bijection, has never been implemented independently. My engine's "Tao" was R_ii itself. Fig. 9 is
a picture without an algorithm. If you know a source that states Tao's puzzle→tableau map as an algorithm, it would let me
test (i) honestly.
